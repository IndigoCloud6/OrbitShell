# SFTP 上传与下载断点续传方案

记录日期：2026-11-12。

状态：**待实现，暂不开发**。用户已明确要求先记录方案；后续收到实现指令后再实施。本文描述规划，不代表当前客户端已具备断点续传能力。

## 方案与范围

沿用现有 Rust、Tokio 与 russh-sftp，实现「持久化任务 + 独立临时文件 + 断点校验 + 按偏移继续」。任务和传输由 Rust 管理，前端只维护任务元信息与真实进度显示。目标是支持断线和应用重启后继续上传、下载普通文件。

| 环节 | 上传 | 下载 |
| --- | --- | --- |
| 传输中 | 使用远端目标目录内的 `.文件名.orbit-任务ID.part`，排他创建 | 使用本地目标目录内同类命名的 `.part` 文件，排他创建 |
| 中断后 | 保留远端临时文件与本机任务记录 | 保留本地临时文件与任务记录 |
| 恢复时 | 校验后将本地源文件和远端临时文件定位到确认断点 | 校验后将远端源文件和本地临时文件定位到确认断点 |
| 完成后 | 关闭并确认写入，再以不覆盖目标的方式重命名提交 | 刷新并落盘，再以不覆盖目标的方式提交 |

## 任务与断点保存

- 在应用数据目录使用独立的 `transfers.json`，不与连接配置混存。
- 保存任务 ID、方向、连接身份关联、源与目标路径、临时文件路径、文件大小、修改时间、确认断点、校验信息和任务状态。
- 原子替换任务记录，避免写到一半留下不可读取的文件；检查点间隔在实施时确定。
- 下载先刷新临时文件并落盘，再保存对应断点；上传以服务器确认写入的数据为依据，恢复时复核远端实际数据。
- SFTP 写入确认不等同于服务器磁盘持久化保证。远端持久化能力需按服务器实际支持情况处理，不作超出协议能力的保证。
- 不保存密码、私钥口令、MCP 令牌、堡垒机认证链接或一次性认证用户名；不持久化 SSH / SFTP 文件句柄和进程内 sessionId 作为恢复依据。

## 恢复校验

- 核对连接身份、主机指纹、规范化路径、源文件大小和修改时间。
- 对断点附近数据块进行内容校验，结合实际临时文件长度确认可继续的位置；不能直接把界面进度或现有文件长度当作可信断点。
- 源文件变化、临时文件异常、身份不符或校验不一致时暂停续传，提示重新开始。
- 默认断点窗口校验只验证相应范围；全文件校验需要另行满足远端校验能力或完整数据比对条件。界面明确展示实际校验范围，不把窗口校验标为全文件校验。
- 续传采用二进制偏移读写，不使用会忽略指定偏移的追加模式，也不截断已验证的有效前缀。

## 文件提交与冲突

- 每个任务只操作自己创建并能确认归属的临时文件，不接管任意同名文件。
- 保留现有上传排他创建语义，正式目标已存在时提示改名，不自动覆盖。
- 临时文件尽量与正式文件处于同一目录，提交时使用不覆盖目标的方式，防止“先检查不存在、再覆盖重命名”的竞争问题。
- 传输、校验、关闭或提交失败时保留可恢复任务；正式文件提交成功后才标记完成。
- 完成提交但确认响应丢失等恢复歧义需核实，不能仅因正式文件存在就认定任务成功。

## 界面与生命周期

- 传输队列增加暂停、继续、重新开始入口，保留清理已完成操作。
- 断线任务显示「等待重新连接」；应用重启后恢复待续传列表，需要先建立符合条件的连接，再继续传输。
- 临时堡垒机会话重新打开链接后，需要确认目标主机一致并通过文件校验；不能仅因堡垒机入口地址相同就自动续传。
- 切换会话或隐藏面板不丢失任务；清理已完成项与历史数量限制不丢弃暂停、等待重连等未完成任务。
- 进度从确认断点继续，速度只计算本轮实际新增字节；保留真实传输进度，不使用计时器模拟进度。
- 暂停或断线保留临时文件；删除临时文件必须是用户明确选择的任务操作。
